# 変更・意思決定の記録

計画書「14. 変更管理計画」に基づき、計画からの変更と、その理由を記録する。
新しいものを上に追記する。

| 日付 | 変更・決定 | 理由 | 影響 |
| - | - | - | - |
| 2026-11-24 | bisync の削除の安全装置は `--max-delete 50`（rclone の既定）のまま明示する。一度 20% にしたが戻した | 20% では、ファイルが少ないフォルダの整理で同期が止まりやすく、手動の対応が増える | 片側の 50% を超える削除で同期が止まる |
| 2026-11-24 | 同期は毎時 00 分・30 分、バックアップは毎日 03:15 の固定時刻にした（`BACKUP_INTERVAL` を廃止し `BACKUP_TIME` を追加） | 計画のリスク「バックアップと同期の同時実行」への対応。起動時刻に依存しない運用にするため | cron ではなく、コンテナ内のループで実装。実行中は印のファイルで排他 |
| 2026-11-24 | 通知を CLOUD（クラウドとローカルの動き）と BACKUP（ローカルと世代管理の動き）に分け、状態が変わったときだけ送る | 失敗の見落としを防ぐ。毎回の通知は読まれなくなるため | 計画外の機能（Bot 拡張の範囲内） |
| 2026-11-24 | 開発モード専用のボタン（復元テスト、世代一覧など）を追加。本番では登録しない | 開発環境で、自動処理を手動で確認できるようにするため | 計画外の機能 |
| 2026-11-24 | 不完全なスナップショットに `partial` タグを付け、次の完全なバックアップで削除する | 不完全なものが世代（日次7・週次2）として数えられるのを防ぐため | restic の世代管理の一部を独自に補う |
| 2026-11-24 | 復元テストに、元データとの網羅性の確認を加えた | バックアップ中の中断で、一部だけのスナップショットが保存される事象が発生したため（[incident-log.md](incident-log.md) の No.4） | 計画外のテスト項目 |
| 2026-11-21 | 開発モードのバックアップ対象を `/config` に変更した（本番は `/data`） | 開発モードでは `/data` が rclone の FUSE マウント（クラウド全体）になり、読み取りが約 0.8MB/s と遅く、ディスクも圧迫するため | 開発環境では、クラウドのデータはバックアップされない |
| 2026-11-21 | 開発モードでは、bisync を行わず、クラウドを直接マウントする | 開発機に、同期用のローカルコピー（SSD 相当）を置かないため | 開発環境では `/sync` は何もしない。bisync は本番モードで検証が必要 |
| 2026-11-21 | Samba は `force user`／`force group` で、rclone・ホストと同じ UID/GID（1000）に統一した | ログインしたユーザーの UID が違い、書き込めなかったため | 認証は残るが、ファイルの所有者は常に 1000 になる |
| 2026-11-21 | Bot と Samba は、`/mnt/data` を親ディレクトリごと `rslave` で bind する | rclone の再起動で、FUSE マウントの参照が切れる（`ENOTCONN`）ため | `DATA_ROOT` 環境変数を追加 |
